## Rotation Collision Verification

### 目的

物体同士の衝突応答に回転を導入したため、見た目だけでなく数値的にも正しく応答しているかを確認した。

主に以下を確認した。

* 衝突前後の法線方向相対速度
* 反発係数との整合性
* 運動量保存
* 接触位置による角速度の変化
* 法線力積によって回転しないケースで不要な回転が発生していないこと

反発係数は `e = 0.75` としているため、単純な1点接触では


`vn_after = -e * vn_before`

となることを期待する。

---

### 1. Rectangle - Triangle：正面衝突

RectangleとTriangleを正面から衝突させた。

```text
vn_before = -200
vn_after  = 150

delta p = (1.52588e-05, 0)

omegaA = -1.79271e-06
omegaB =  4.29647e-06
```

#### 結果

* `vn_after = -0.75 * vn_before` となっており、反発係数と一致した。
* 衝突前後の全運動量の差はほぼ0だった。
* 接触点が重心を通る正面衝突なので、角速度の変化もほぼ0となった。

正面衝突では不要な回転が発生しないことを確認できた。

---

### 2. Rectangle - Triangle：オフセンター衝突

Triangleを45度回転させ、Triangleの先端がRectangleの右上付近へ衝突する条件で確認した。

```text
vn_before = -200
vn_after  = 150

delta p = (3.8147e-05, 0)

omegaA = -2.14395
omegaB =  2.9801
```

#### 結果

* 法線方向相対速度は反発係数と一致した。
* 運動量の差もほぼ0だった。
* 重心からずれた位置に力積が作用したことで、両物体に角速度が発生した。
* 回転方向も接触位置から予想した方向と一致した。

接触位置によってトルクが発生し、並進運動の一部が回転運動へ変化することを確認できた。

---

### 3. Circle - Polygon

CircleをA、PolygonをBとして衝突させた。

```text
vn_before = -164.521
vn_after  = 123.391

delta p = (0, 0)

omegaA = 0
omegaB = -3.71883
```

#### 結果

* 法線方向相対速度は反発係数と一致した。
* 運動量も保存されていた。
* Circle側では角速度が変化しなかった。
* Polygon側には角速度が発生した。

円の接触腕は法線方向と平行になるため、法線力積による

`r cross J`

が0となり、Circleには回転が発生しない。この結果と一致した。

---

### 4. Circle - Circle

Circle同士を衝突させた。

```text
vn_before = -25.1436
vn_after  = 18.8577

delta p = (1.52588e-05, 0)

omegaA = -2.03631e-07
omegaB =  3.17795e-08
```

#### 結果

* 法線方向相対速度は反発係数と一致した。
* 運動量の差はほぼ0だった。
* 両Circleの角速度変化もほぼ0だった。

Circle同士では両物体とも接触腕と法線が平行になるため、法線力積だけでは回転しないという理論と一致した。

---

### まとめ

今回の確認により、

* 接触点速度を用いた法線方向相対速度
* 回転を含む有効質量
* 法線力積
* `r × J` による角速度更新

について、代表的な衝突条件では期待した挙動をしていることを確認した。

特に、

* 重心を通る衝突では回転しない
* 重心から外れた衝突では回転する
* Circleへの法線力積では回転しない

という、回転応答の基本的な性質を数値と挙動の両方から確認できた。

現時点では手動で数値確認を行った。今後PhysicsLabの構造が安定した段階で、これらの条件の一部を自動テストへ移行することを検討する。

---

## 壁の回転応答時の回転速度について
- 地面衝突時の回転が速く見えたため、mass / inertia / r×n / angular velocityを確認。
- 同程度のr×nでは慣性モーメントが大きい物体ほど角速度変化が小さく、
  inertiaが大きくてもr×nが大きい場合は十分な回転が発生することを確認。
- 回転応答は計算意図と一致していると判断し、現時点では調整しない。

## 摩擦実装の数値検証

### 目的

回転を考慮した剛体衝突に摩擦力積を追加したため、摩擦が意図した通りに作用しているかを数値で確認した。

今回の摩擦では、法線力積 `Jn` を適用した後の接触点相対速度から接線方向成分 `vt` を求め、

```text
Jt = -vt / effectiveMassTangent
```

によって接線方向の力積を計算している。

また、Coulomb摩擦として、

```text
|Jt| <= μ |Jn|
```

となるように摩擦力積を制限している。

---

### 確認した項目

以下を衝突ごとに出力して確認した。

* 法線方向相対速度 `vn`
* 法線力積適用後と摩擦力積適用後の接線方向相対速度 `vt`
* 摩擦力積が `μJn` の範囲内に収まっているか
* 衝突前後の全線形運動量
* 並進＋回転を含む全運動エネルギー
* 各物体の角速度

特に摩擦の効果については、物体の質量やサイズを固定して条件を完全一致させるのではなく、

```text
Jn適用後の |vt|
↓
Jt適用後の |vt|
```

の変化を比較した。

これにより、ランダムな質量・形状・衝突位置であっても、摩擦力積そのものによる変化を確認できる。


μ = 0 と μ = 0.5 では実行時の衝突条件が異なるため、両者の減少量そのものを定量的には比較していない。
各衝突において、摩擦力積を適用した前後で |vt| がどのように変化するかを確認した。

---

### 摩擦なしの場合

条件：

```text
restitution = 0.75
μ = 0
```

結果例：

```text
vn_bef = -300.261
vn_aft = 225.196

vt decrease = 0

p_bef = (-129.835, 269.981)
p_aft = (-129.835, 269.981)

K_bef = 74555.2
K_aft = 63691.7
```

別の衝突でも、

```text
vn_bef = -385.489
vn_aft = 289.117

vt decrease = 0

p_bef = (-129.835, 316.626)
p_aft = (-129.835, 316.626)
```

となった。

`μ = 0` のため摩擦力積は0となり、法線力積適用後から接線方向相対速度 `vt` は変化しなかった。

---

### 摩擦ありの場合

条件：

```text
restitution = 0.75
μ = 0.5
```

結果例：

```text
vn_bef = -350.489
vn_aft = 262.867

vt decrease = 141.993

|Jt| <= μJn : true

p_bef = (-74.8918, 185.857)
p_aft = (-74.8918, 185.857)

K_bef = 46475.6
K_aft = 28621.4

omegaA = -1.65189
omegaB = 5.10011
```

摩擦なしでは `vt decrease = 0` だったのに対し、摩擦ありでは接線方向相対速度が明確に減少した。

したがって、摩擦力積によって接触点の滑りが抑えられていることを確認できた。

---

### 法線方向の確認

法線方向については、

```text
vn_after ≈ -e × vn_before
```

となることを確認した。

例えば、

```text
vn_bef = -350.489
vn_aft = 262.867
```

であり、

```text
350.489 × 0.75 ≈ 262.867
```

となっている。

摩擦処理を追加した後も、反発係数による法線方向の衝突応答は崩れていない。

---

### 線形運動量の確認

物体同士の衝突では、

```text
A : -J
B : +J
```

として法線力積・摩擦力積をそれぞれ逆向きに作用させている。

実際に、

```text
p_bef = (-74.8918, 185.857)
p_aft = (-74.8918, 185.857)
```

となり、数値誤差の範囲で全線形運動量が保存されていることを確認した。

摩擦によって各物体の並進速度や角速度は変化しているが、物体2つを合わせた系全体の線形運動量は保存されている。

---

### エネルギーについて

衝突後は全運動エネルギーが減少した。

```text
K_bef = 46475.6
K_aft = 28621.4
```

今回の `K_bef` は法線力積適用前、`K_aft` は法線力積と摩擦力積の両方を適用した後である。

そのため、このエネルギー減少には、

* 反発係数 `e = 0.75` による非弾性衝突の損失
* 摩擦による接線方向のエネルギー損失

の両方が含まれている。

したがって、摩擦単体の効果についてはエネルギー減少量ではなく、`Jn` 適用後から `Jt` 適用後までの `vt` の減少を主な確認指標とした。

---

### 見た目の変化

摩擦を追加したことで、見た目にも大きな改善があった。

* 衝突後の滑りが減少した
* 過剰に残っていた回転が抑えられた
* 並進運動も比較的早く落ち着くようになった
* 辺接触状態での静止が以前より自然になった
* 物体同士の辺接触や寄りかかり状態も比較的安定した

摩擦は角速度そのものを直接小さくする処理ではなく、接触点の相対接線速度を減らす処理である。

その結果として、今回のシーンでは滑りだけでなく、過剰な回転も抑えられる挙動になった。

---

### 現時点で残っている課題

現在は1つの接触点のみを用いて衝突応答している。

そのため、初めから辺接触している場合などでは、片方の接触点に力積を作用させることで一時的に回転が発生する。

ただし、摩擦導入後はその回転も比較的早く減衰し、以前より自然に静止するようになった。

また、物体が他の物体へ寄りかかった状態では、微小な運動が継続することで最終的に姿勢が崩れる場合がある。

この問題については今後、

* 複数接触点
* Contact Manifold
* Solver Iteration
* Sequential Impulse
* Sleep

などを導入して改善していく。

---

### 結論

今回の検証から、摩擦実装について以下を確認できた。

```text
μ = 0
→ Jt = 0
→ vt decrease = 0

μ > 0
→ 摩擦力積が発生
→ |vt| が減少
```

さらに、

```text
vn_after ≈ -e × vn_before
|Jt| <= μ|Jn|
p_before ≈ p_after
```

も成立している。

以上から、現在の摩擦力積は意図した方向・大きさで作用しており、法線方向の衝突応答や線形運動量保存を壊さずに、接触点の滑りを減少させられていることを確認した。

## Sequential Impulse：iteration回数による接触点修正の確認

### 目的

複数接触点を持つ衝突について、Sequential Impulse の iteration を増やすことで、各接触点が相互に与える影響を再評価・修正できているか確認した。

同一の初期条件で、

- iteration = 1
- iteration = 5

を比較した。

### 確認結果

iteration = 1 の場合、各接触点を1回ずつ処理した時点でそのフレームの衝突応答が終了する。

代表例では、

```text
contact 0:
    vn before = -310.361
    Jn = 73.2234

contact 1:
    vn before = -356.912
    Jn = 93.0796
```

となった。

一方、iteration = 5 では、iteration 0 で同じ処理を行った後、iteration 1 で contact 0 の法線方向相対速度が再び

```text
vn before = -15.2303
```

となっていた。

これは、contact 0 の処理後に contact 1 へ力積を適用したことで Body の並進速度・角速度が変化し、先に処理した contact 0 が再び接近状態になったためと考えられる。

iteration 1 では contact 0 に対して追加の法線力積

```text
Jn = 3.59329
```

が適用され、その後の iteration 2 では

```text
vn before = 13.7073
```

となり、接近状態が解消された。

### 分かったこと

複数接触点を逐次処理する場合、後から処理した接触点の力積によって、先に処理した接触点の速度状態が変化することを確認した。

iteration を複数回行うことで、

```text
contact 0を処理
    ↓
contact 1を処理
    ↓
contact 1の応答によってcontact 0の状態が変化
    ↓
次iterationでcontact 0を再評価・修正
```

という処理が実際に行われている。

また、初回の大きな力積に対して、次iterationでは残った接近速度に対応する比較的小さな力積が適用されており、修正量が小さくなる挙動も確認できた。

十分に `vn > 0` となった接触点については、それ以降のiterationで追加の法線力積は発生していない。

以上から、iterationループによって接触点間の相互作用を反復的に修正する処理自体は機能していると判断した。

### 今後の確認

今回確認できたのは、iterationによって接触点間の影響を再評価・修正できることまでである。

今後は以下を確認する。

- 接触点ごとの累積法線力積を導入する
- restitutionを反復ソルバ向けの扱いに整理する
  iterationを増やしても「反発係数0.9なら、その衝突で一度だけ0.9相当の反発をする」という意味を保てるようにする。

---
### 累積法線力積の導入と反復収束の確認

Sequential Impulse における法線応答を、各 iteration で単発の力積を適用する方式から、接触点ごとに法線力積を累積する方式へ変更した。

各接触点では、現在の法線方向相対速度から補正用の法線力積 `deltaJn` を求め、既存の累積法線力積へ加算する。累積値は 0 未満にならないよう制限し、実際に物体へ適用する力積は、更新前後の累積値の差分とした。

これにより、別の接触点を処理した結果として以前の法線力積が過剰になった場合、負の `deltaJn` によって過去に与えた力積の一部を取り消せる。一方で、累積法線力積そのものは負にならないため、接触面が物体を引き戻す方向の力積は発生しない。

#### 検証条件

- 矩形 2 個を上下方向に接触させる
- 上側の矩形を水平方向に少しずらして配置
- 上側の矩形のみに下向き初速度を与える
- 初期角速度は両方 0
- restitution = 0
- friction = 0
- 法線応答のみ有効
- solver iteration = 10

#### 確認結果

最初の iteration では両接触点に正の法線力積が加わった。

その後、片方の接触点では別接触点の処理によって法線方向相対速度が正となり、負の補正力積が発生した。

例：

```text
iteration = 1
contact 0:
    vn before = 7.37744
    deltaJn = -1.43267
    oldAccumJn = 5.82589
    newAccumJn = 4.39321
```

この結果から、以前に累積した法線力積を一部取り消す方向の修正が実際に行われていることを確認した。

一方、もう一方の接触点では正の補正力積が継続して加わり、iteration を重ねるにつれて両接触点の累積法線力積が近い値へ収束した。

```text
contact 0 accumulated Jn ≈ 4.056
contact 1 accumulated Jn ≈ 4.056
```

法線方向相対速度も 0 付近へ収束し、両物体の角速度もほぼ同じ値へ近づいた。

以上から、複数接触点間の相互作用を反復処理しながら、法線力積を増減させて接触解を収束させる動作を確認した。

なお、累積値が 0 を下回ろうとして clamp が実際に発動するケースの数値確認までは行っていない。実装上は累積法線力積を 0 以上に制限し、clamp 後の値を接触点へ保持している。

### 今後の実装内容
- restitutionを反復ソルバ向けの扱いに整理する
  iterationを増やしても「反発係数0.9なら、その衝突で一度だけ0.9相当の反発をする」という意味を保てるようにする。
