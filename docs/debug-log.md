## Rotation Collision Verification

### 目的

物体同士の衝突応答に回転を導入したため、見た目だけでなく数値的にも正しく応答しているかを確認した。

主に以下を確認した。

* 衝突前後の法線方向相対速度
* 反発係数との整合性
* 運動量保存
* 接触位置による角速度の変化
* 法線力積によって回転しないケースで不要な回転が発生していないこと

反発係数は `e = 0.75` としているため、単純な1点接触では


`vn_after = -e * vn_before`

となることを期待する。

---

### 1. Rectangle - Triangle：正面衝突

RectangleとTriangleを正面から衝突させた。

```text
vn_before = -200
vn_after  = 150

delta p = (1.52588e-05, 0)

omegaA = -1.79271e-06
omegaB =  4.29647e-06
```

#### 結果

* `vn_after = -0.75 * vn_before` となっており、反発係数と一致した。
* 衝突前後の全運動量の差はほぼ0だった。
* 接触点が重心を通る正面衝突なので、角速度の変化もほぼ0となった。

正面衝突では不要な回転が発生しないことを確認できた。

---

### 2. Rectangle - Triangle：オフセンター衝突

Triangleを45度回転させ、Triangleの先端がRectangleの右上付近へ衝突する条件で確認した。

```text
vn_before = -200
vn_after  = 150

delta p = (3.8147e-05, 0)

omegaA = -2.14395
omegaB =  2.9801
```

#### 結果

* 法線方向相対速度は反発係数と一致した。
* 運動量の差もほぼ0だった。
* 重心からずれた位置に力積が作用したことで、両物体に角速度が発生した。
* 回転方向も接触位置から予想した方向と一致した。

接触位置によってトルクが発生し、並進運動の一部が回転運動へ変化することを確認できた。

---

### 3. Circle - Polygon

CircleをA、PolygonをBとして衝突させた。

```text
vn_before = -164.521
vn_after  = 123.391

delta p = (0, 0)

omegaA = 0
omegaB = -3.71883
```

#### 結果

* 法線方向相対速度は反発係数と一致した。
* 運動量も保存されていた。
* Circle側では角速度が変化しなかった。
* Polygon側には角速度が発生した。

円の接触腕は法線方向と平行になるため、法線力積による

`r cross J`

が0となり、Circleには回転が発生しない。この結果と一致した。

---

### 4. Circle - Circle

Circle同士を衝突させた。

```text
vn_before = -25.1436
vn_after  = 18.8577

delta p = (1.52588e-05, 0)

omegaA = -2.03631e-07
omegaB =  3.17795e-08
```

#### 結果

* 法線方向相対速度は反発係数と一致した。
* 運動量の差はほぼ0だった。
* 両Circleの角速度変化もほぼ0だった。

Circle同士では両物体とも接触腕と法線が平行になるため、法線力積だけでは回転しないという理論と一致した。

### まとめ

今回の確認により、

* 接触点速度を用いた法線方向相対速度
* 回転を含む有効質量
* 法線力積
* `r × J` による角速度更新

について、代表的な衝突条件では期待した挙動をしていることを確認した。

特に、

* 重心を通る衝突では回転しない
* 重心から外れた衝突では回転する
* Circleへの法線力積では回転しない

という、回転応答の基本的な性質を数値と挙動の両方から確認できた。

## 壁の回転応答時の回転速度について
- 地面衝突時の回転が速く見えたため、mass / inertia / r×n / angular velocityを確認。
- 同程度のr×nでは慣性モーメントが大きい物体ほど角速度変化が小さく、
  inertiaが大きくてもr×nが大きい場合は十分な回転が発生することを確認。
- 回転応答は計算意図と一致していると判断し、現時点では調整しない。

## 摩擦実装の数値検証

### 目的

回転を考慮した剛体衝突に摩擦力積を追加したため、摩擦が意図した通りに作用しているかを数値で確認した。

今回の摩擦では、法線力積 `Jn` を適用した後の接触点相対速度から接線方向成分 `vt` を求め、

```text
Jt = -vt / effectiveMassTangent
```

によって接線方向の力積を計算している。

また、Coulomb摩擦として、

```text
|Jt| <= μ |Jn|
```

となるように摩擦力積を制限している。

---

### 確認した項目

以下を衝突ごとに出力して確認した。

* 法線方向相対速度 `vn`
* 法線力積適用後と摩擦力積適用後の接線方向相対速度 `vt`
* 摩擦力積が `μJn` の範囲内に収まっているか
* 衝突前後の全線形運動量
* 並進＋回転を含む全運動エネルギー
* 各物体の角速度

特に摩擦の効果については、物体の質量やサイズを固定して条件を完全一致させるのではなく、

```text
Jn適用後の |vt|
↓
Jt適用後の |vt|
```

の変化を比較した。

これにより、ランダムな質量・形状・衝突位置であっても、摩擦力積そのものによる変化を確認できる。


μ = 0 と μ = 0.5 では実行時の衝突条件が異なるため、両者の減少量そのものを定量的には比較していない。
各衝突において、摩擦力積を適用した前後で |vt| がどのように変化するかを確認した。

---

### 摩擦なしの場合

条件：

```text
restitution = 0.75
μ = 0
```

結果例：

```text
vn_bef = -300.261
vn_aft = 225.196

vt decrease = 0

p_bef = (-129.835, 269.981)
p_aft = (-129.835, 269.981)

K_bef = 74555.2
K_aft = 63691.7
```

別の衝突でも、

```text
vn_bef = -385.489
vn_aft = 289.117

vt decrease = 0

p_bef = (-129.835, 316.626)
p_aft = (-129.835, 316.626)
```

となった。

`μ = 0` のため摩擦力積は0となり、法線力積適用後から接線方向相対速度 `vt` は変化しなかった。

---

### 摩擦ありの場合

条件：

```text
restitution = 0.75
μ = 0.5
```

結果例：

```text
vn_bef = -350.489
vn_aft = 262.867

vt decrease = 141.993

|Jt| <= μJn : true

p_bef = (-74.8918, 185.857)
p_aft = (-74.8918, 185.857)

K_bef = 46475.6
K_aft = 28621.4

omegaA = -1.65189
omegaB = 5.10011
```

摩擦なしでは `vt decrease = 0` だったのに対し、摩擦ありでは接線方向相対速度が明確に減少した。

したがって、摩擦力積によって接触点の滑りが抑えられていることを確認できた。

---

### 法線方向の確認

法線方向については、

```text
vn_after ≈ -e × vn_before
```

となることを確認した。

例えば、

```text
vn_bef = -350.489
vn_aft = 262.867
```

であり、

```text
350.489 × 0.75 ≈ 262.867
```

となっている。

摩擦処理を追加した後も、反発係数による法線方向の衝突応答は崩れていない。

---

### 線形運動量の確認

物体同士の衝突では、

```text
A : -J
B : +J
```

として法線力積・摩擦力積をそれぞれ逆向きに作用させている。

実際に、

```text
p_bef = (-74.8918, 185.857)
p_aft = (-74.8918, 185.857)
```

となり、数値誤差の範囲で全線形運動量が保存されていることを確認した。

摩擦によって各物体の並進速度や角速度は変化しているが、物体2つを合わせた系全体の線形運動量は保存されている。

---

### エネルギーについて

衝突後は全運動エネルギーが減少した。

```text
K_bef = 46475.6
K_aft = 28621.4
```

今回の `K_bef` は法線力積適用前、`K_aft` は法線力積と摩擦力積の両方を適用した後である。

そのため、このエネルギー減少には、

* 反発係数 `e = 0.75` による非弾性衝突の損失
* 摩擦による接線方向のエネルギー損失

の両方が含まれている。

したがって、摩擦単体の効果についてはエネルギー減少量ではなく、`Jn` 適用後から `Jt` 適用後までの `vt` の減少を主な確認指標とした。

---

### 見た目の変化

摩擦を追加したことで、見た目にも大きな改善があった。

* 衝突後の滑りが減少した
* 過剰に残っていた回転が抑えられた
* 並進運動も比較的早く落ち着くようになった
* 辺接触状態での静止が以前より自然になった
* 物体同士の辺接触や寄りかかり状態も比較的安定した

摩擦は角速度そのものを直接小さくする処理ではなく、接触点の相対接線速度を減らす処理である。

その結果として、今回のシーンでは滑りだけでなく、過剰な回転も抑えられる挙動になった。

---

### 現時点で残っている課題

現在は1つの接触点のみを用いて衝突応答している。

そのため、初めから辺接触している場合などでは、片方の接触点に力積を作用させることで一時的に回転が発生する。

ただし、摩擦導入後はその回転も比較的早く減衰し、以前より自然に静止するようになった。

また、物体が他の物体へ寄りかかった状態では、微小な運動が継続することで最終的に姿勢が崩れる場合がある。

この問題については今後、

* 複数接触点
* Contact Manifold
* Solver Iteration
* Sequential Impulse
* Sleep

などを導入して改善していく。

---

### 結論

今回の検証から、摩擦実装について以下を確認できた。

```text
μ = 0
→ Jt = 0
→ vt decrease = 0

μ > 0
→ 摩擦力積が発生
→ |vt| が減少
```

さらに、

```text
vn_after ≈ -e × vn_before
|Jt| <= μ|Jn|
p_before ≈ p_after
```

も成立している。

以上から、現在の摩擦力積は意図した方向・大きさで作用しており、法線方向の衝突応答や線形運動量保存を壊さずに、接触点の滑りを減少させられていることを確認した。

## Sequential Impulse：iteration回数による接触点修正の確認

### 目的

複数接触点を持つ衝突について、Sequential Impulse の iteration を増やすことで、各接触点が相互に与える影響を再評価・修正できているか確認した。

同一の初期条件で、

- iteration = 1
- iteration = 5

を比較した。

### 確認結果

iteration = 1 の場合、各接触点を1回ずつ処理した時点でそのフレームの衝突応答が終了する。

代表例では、

```text
contact 0:
    vn before = -310.361
    Jn = 73.2234

contact 1:
    vn before = -356.912
    Jn = 93.0796
```

となった。

一方、iteration = 5 では、iteration 0 で同じ処理を行った後、iteration 1 で contact 0 の法線方向相対速度が再び

```text
vn before = -15.2303
```

となっていた。

これは、contact 0 の処理後に contact 1 へ力積を適用したことで Body の並進速度・角速度が変化し、先に処理した contact 0 が再び接近状態になったためと考えられる。

iteration 1 では contact 0 に対して追加の法線力積

```text
Jn = 3.59329
```

が適用され、その後の iteration 2 では

```text
vn before = 13.7073
```

となり、接近状態が解消された。

### 分かったこと

複数接触点を逐次処理する場合、後から処理した接触点の力積によって、先に処理した接触点の速度状態が変化することを確認した。

iteration を複数回行うことで、

```text
contact 0を処理
    ↓
contact 1を処理
    ↓
contact 1の応答によってcontact 0の状態が変化
    ↓
次iterationでcontact 0を再評価・修正
```

という処理が実際に行われている。

また、初回の大きな力積に対して、次iterationでは残った接近速度に対応する比較的小さな力積が適用されており、修正量が小さくなる挙動も確認できた。

十分に `vn > 0` となった接触点については、それ以降のiterationで追加の法線力積は発生していない。

以上から、iterationループによって接触点間の相互作用を反復的に修正する処理自体は機能していると判断した。

### 今後の確認

今回確認できたのは、iterationによって接触点間の影響を再評価・修正できることまでである。

今後は以下を確認する。

- 接触点ごとの累積法線力積を導入する
- restitutionを反復ソルバ向けの扱いに整理する
  iterationを増やしても「反発係数0.9なら、その衝突で一度だけ0.9相当の反発をする」という意味を保てるようにする。

---
### 累積法線力積の導入と反復収束の確認

Sequential Impulse における法線応答を、各 iteration で単発の力積を適用する方式から、接触点ごとに法線力積を累積する方式へ変更した。

各接触点では、現在の法線方向相対速度から補正用の法線力積 `deltaJn` を求め、既存の累積法線力積へ加算する。累積値は 0 未満にならないよう制限し、実際に物体へ適用する力積は、更新前後の累積値の差分とした。

これにより、別の接触点を処理した結果として以前の法線力積が過剰になった場合、負の `deltaJn` によって過去に与えた力積の一部を取り消せる。一方で、累積法線力積そのものは負にならないため、接触面が物体を引き戻す方向の力積は発生しない。

#### 検証条件

- 矩形 2 個を上下方向に接触させる
- 上側の矩形を水平方向に少しずらして配置
- 上側の矩形のみに下向き初速度を与える
- 初期角速度は両方 0
- restitution = 0
- friction = 0
- 法線応答のみ有効
- solver iteration = 10

#### 確認結果

最初の iteration では両接触点に正の法線力積が加わった。

その後、片方の接触点では別接触点の処理によって法線方向相対速度が正となり、負の補正力積が発生した。

例：

```text
iteration = 1
contact 0:
    vn before = 7.37744
    deltaJn = -1.43267
    oldAccumJn = 5.82589
    newAccumJn = 4.39321
```

この結果から、以前に累積した法線力積を一部取り消す方向の修正が実際に行われていることを確認した。

一方、もう一方の接触点では正の補正力積が継続して加わり、iteration を重ねるにつれて両接触点の累積法線力積が近い値へ収束した。

```text
contact 0 accumulated Jn ≈ 4.056
contact 1 accumulated Jn ≈ 4.056
```

法線方向相対速度も 0 付近へ収束し、両物体の角速度もほぼ同じ値へ近づいた。

以上から、複数接触点間の相互作用を反復処理しながら、法線力積を増減させて接触解を収束させる動作を確認した。

なお、累積値が 0 を下回ろうとして clamp が実際に発動するケースの数値確認までは行っていない。実装上は累積法線力積を 0 以上に制限し、clamp 後の値を接触点へ保持している。

### 今後の実装内容
- restitutionを反復ソルバ向けの扱いに整理する
  iterationを増やしても「反発係数0.9なら、その衝突で一度だけ0.9相当の反発をする」という意味を保てるようにする。

## Contact Solver：restitution目標速度方式への変更と検証

### 目的

Sequential Impulseにおいて、従来の単発衝突式 `-(1 + e) * vn / K` を各iterationで使用する方式から、衝突開始時の法線方向相対速度に基づく目標速度方式へ変更した。

各接触点の初期法線速度を `vnInitial` とし、反発目標速度を `targetVel = -e * vnInitial` としてiteration開始前に設定する。各iterationでは現在の `vnCurrent` と固定された `targetVel` との差から補正力積を求め、既存の累積法線力積へ反映する。

### 検証条件

- 対象：上下配置された剛体の正面衝突
- 接触点数：2
- restitution：0、0.5
- iteration数：1、5、10
- 記録値：`vnInitial`、`targetVel`、`vnCurrent`、`deltaJn`、`accJn`

### 検証1：restitution = 0

目標速度はいずれの接触点も0となった。

| 項目 | Contact 0 | Contact 1 |
|---|---:|---:|
| vnInitial | -299.574 | -303.800 |
| targetVel | 0 | 0 |
| iteration 9のvnCurrent | -0.000427 | -0.000183 |
| 最終accJn | 66.9938 | 67.3510 |

iterationを繰り返すことで両接触点の法線速度が0に収束した。

また、従来方式でもrestitution = 0の場合は補正力積の計算式が新方式と等価になるため、最終ログの数値に差はなかった。

### 検証2：restitution = 0.5

各接触点について、初期法線速度から目標反発速度を設定した。

| 項目 | Contact 0 | Contact 1 |
|---|---:|---:|
| vnInitial | -299.574 | -303.800 |
| targetVel | 149.787 | 151.900 |
| iteration 9のvnCurrent | 149.786 | 151.900 |
| 最終accJn | 100.491 | 101.027 |

10iteration時点で、両接触点の法線速度が目標値にほぼ収束した。

また、iteration数を1、5、10と変更して比較した結果、反復回数が増えるにつれて各接触点の法線速度が目標値へ近づくことを確認した。

### 考察

1つの接触点に力積を適用すると、剛体の並進速度および角速度が変化し、ほかの接触点の相対速度にも影響する。

そのため、各接触点で単発衝突式を1回適用するだけでは、すべての接触点の拘束を同時に満たせない場合がある。

Sequential Impulseでは、複数の接触点を反復処理することで互いの影響を調整し、目標速度への収束を図る。

今回の目標速度方式では、初期法線速度に基づく反発目標を固定し、各iterationでその目標との差を補正することで、restitution = 0および0.5の両条件で良好な収束が確認できた。

### 結果と残る確認事項

- restitution = 0で、法線速度が0に収束することを確認した。
- restitution = 0.5で、法線速度が固定目標値へ収束することを確認した。
- iteration数を増やすことで、2接触点の拘束の収束精度が改善することを確認した。
- 今回のログでは、累積法線力積の負方向更新が発生する条件は未検証。
  一個前の検証で確認できており、変更もしていないため、未検証。
- restitution threshold、累積摩擦、stackingの検証は今後実施する。

## Contact Solver：累積接線力積によるCoulomb摩擦の検証

### 目的

Sequential Impulseによる接触ソルバに、累積接線力積を用いたCoulomb摩擦を実装し、以下を確認した。

- 接触点ごとに接線力積を累積できること
- 累積法線力積に応じて摩擦力積を制限できること
- 各iterationで累積値の更新差分のみを適用できること
- 摩擦係数の違いが物体の速度と積み重なり挙動に反映されること

### 実装内容

接触点での接線方向相対速度 \(v_t\) と接線方向の有効質量から、補正力積 \(\Delta J_t\) を求める。

\[
\Delta J_t = -\frac{v_t}{m_{\mathrm{eff},t}}
\]

接触点ごとに累積接線力積を保持し、累積法線力積 \(J_n^{acc}\) に基づいて制限する。

\[
J_t^{new} =
\operatorname{clamp}
\left(
J_t^{old}+\Delta J_t,\,
-\mu J_n^{acc},\,
+\mu J_n^{acc}
\right)
\]

実際に適用する力積は、累積値の更新差分とする。

\[
J_t^{apply}=J_t^{new}-J_t^{old}
\]

### 検証1：摩擦係数による比較

同一初期条件で、摩擦係数 `μ = 0` と `μ = 0.5` を比較した。接触点は2点、iteration数は10回とした。

**μ = 0**

- `maxFriction = 0` となり、累積接線力積は0に制限された。
- `ΔJt` が計算されても、実際に適用する接線力積は0となった。
- 摩擦処理前後で物体の速度が変化しないことを確認した。

**μ = 0.5**

- 接触点ごとに累積接線力積が更新された。
- iterationを重ねるにつれて補正力積が小さくなり、収束する傾向を確認した。
- contact 0の累積接線力積は約 `14.05`、contact 1は約 `-13.84` となった。
- 最終付近の補正力積は `10^-4` 程度まで減少した。
- 累積接線力積が摩擦上限を超えないことを確認した。

この条件では摩擦上限に到達しなかったため、clampが実際に発動する挙動は別条件で検証した。

### 検証2：Coulomb摩擦制限の確認

摩擦係数を `μ = 0.05` に変更し、摩擦上限が小さい条件で検証した。

**contact 0（iteration 0）**

```text
deltaJt = 7.9504
maxFriction = 2.79034
oldAccumJt = 0
newAccumJt = 2.79034
frictionImpulse = 2.79034
```

補正力積の要求値が摩擦上限を超えたため、累積接線力積が正方向の上限 `+2.79034` に制限された。

**contact 1（iteration 0）**

```text
deltaJt = -5.95212
maxFriction = 4.05636
oldAccumJt = 0
newAccumJt = -4.05636
frictionImpulse = -4.05636
```

負方向についても累積接線力積が下限 `-4.05636` に制限された。

これにより、Coulomb摩擦による正負両方向のclampが正常に機能することを確認した。

### 検証3：摩擦上限到達時の接線相対速度

累積接線力積による摩擦処理について、iteration終了時に接線方向相対速度 \(v_t\) が0に収束しないケースを確認した。

接線方向のソルバは、摩擦制限の範囲内で \(v_t\) を0に近づける。しかし、必要な補正力積がCoulomb摩擦の上限を超える場合、接線方向の相対速度が残る。

今回、2接触点・iteration数10回の条件で、以下の挙動を確認した。

**摩擦上限に到達していないケース**

- iterationを重ねるにつれて補正力積が減少した。
- 接触点の `vt` が0に近づくことを確認した。
- `μ = 0.5` の検証では、最終付近の補正力積が `10^-4` 程度となった。

**摩擦上限に到達したケース**

接触開始直後の別の時間ステップにおいて、摩擦上限へ到達し、接線相対速度が残るケースを確認した。

iteration 9のログ：

```text
contact 0
    vt_bef = -25.0374
    deltaJt = 8.52501
    maxFriction = 4.18128
    oldAccumJt = 4.18128
    newAccumJt = 4.18128
    frictionImpulse ≈ 0
    vt_aft = -25.0374

contact 1
    vt_bef = -24.8349
    deltaJt = 8.45992
    maxFriction = 8.81471
    oldAccumJt = 8.81471
    newAccumJt = 8.81471
    frictionImpulse ≈ 0
    vt_aft = -24.8349
```

両接触点で累積接線力積が摩擦上限に達しており、追加の補正力積を適用できない状態となっていた。

そのため、iterationを重ねても `vt` は0にならず、接線方向の相対運動が残った。

この結果から、**累積接線力積の更新差分が0に近づくことと、接線相対速度が0に近づくことは必ずしも一致しない**と確認できた。

摩擦上限に到達していない場合は \(v_t \to 0\) を目指し、上限に到達した場合は滑りを許容しながらCoulomb摩擦制限を守る。

今回のログは、この摩擦制限付き接触ソルバの動作と整合している。

なお、本検証は摩擦処理の挙動を確認したものであり、接触状態全体の長時間安定性を保証するものではない。

### 描画による確認

矩形の積み重ねにおいて、摩擦係数による挙動の違いを観察した。

- `μ = 0`：矩形に横方向のずれが生じ、積み重なりが維持されにくかった。
- `μ = 0.5`：横方向のずれが抑えられ、2個の矩形が安定して積み重なる様子を確認した。
- 4個の矩形でも積み重なりは改善したが、時間経過に伴う小さな位置のずれが残った。

### 結果と今後の課題

累積接線力積の更新、更新差分による力積適用、Coulomb摩擦制限の動作を数値ログから確認できた。

また、摩擦係数の違いによって積み重なりの安定性が改善することを描画から確認した。

一方、4個の矩形ではドリフトが残っている。今回の検証は反復内の摩擦応答を中心としたものであり、長時間の静止接触の安定性は未検証である。

今後は静的な床・壁の共通ソルバ化と、低速反発・位置補正・静止接触の安定化を進め、複数物体の長時間の積み重ねを検証する。

## Phase 5：Restitution Thresholdの導入と検証

### 目的

低速接触において不要な反発が発生することを防ぐため、restitution thresholdを導入した。

衝突開始時の法線方向相対速度 `vnInit` に応じて反発目標速度 `targetVel` を設定し、低速接近では反発を発生させず、接近速度を0へ近づけることを目的とする。

### 実装内容

反発目標速度の初期値を0とし、接近速度がthresholdを超える場合のみ反発係数に基づく目標速度を設定する。

```cpp
contact.targetVel = 0.0f;

if (vnInit < -RESTITUTIONTHRESHOLD) {
    contact.targetVel = -OBJRESTITUTION * vnInit;
}
```

これにより、低速接近および非接近時には反発目標速度を設定しない。

### 検証条件

- 対象：矩形2個による上下方向の正面衝突
- 重力：0
- 反発係数：0.8
- 摩擦係数：0
- Restitution Threshold：10.0
- 初期回転：なし
- 接触点：2点
- Solver Iterations：基本10回

上側矩形のY方向初速度を変更し、接近速度に応じたtargetVelと、各iterationにおけるvnの変化を確認した。

### 検証結果

| 接近速度 | targetVel | 結果 |
|---|---|---|
| 5 | 0 | 両接触点のvnがほぼ0に収束 |
| 10 | 0 | 境界値では反発目標速度を設定しない |
| 20 | 16 | 両接触点のvnが16に収束 |
| 100 | 80 | 両接触点のvnが約80に収束 |

低速接近（5）では、両接触点のvnがiterationの進行に伴って0へ収束した。

高速接近（20）では、両接触点のvnが最終的に16となり、設定した反発目標速度に一致した。

高速接近（100）でも、両接触点のvnが約80に収束した。

これにより、thresholdによる反発の切り替えと、Sequential Impulseによる目標速度への収束を確認できた。

### 追加確認

- 反発係数e=0の場合、thresholdに関係なくtargetVel=0となることを確認。
- 初速度を離反方向へ設定した場合、接触は発生しなかった。
- 非接近時にはtargetVel=0となる実装条件を確認。
- iteration数を1、5、10に変更し、目視上、不自然な過剰反発が発生しないことを確認。

### 残る検証

重力下での反発も観察したが、下側の矩形も動的物体であるため、想定した静的床上での連続反発とは異なる挙動となった。

現状では壁衝突が共通Contact Solverに統合されていないため、低速での連続反発や静止接触の安定性についてはPhase 6で検証する。

### 結論

今回の条件では、restitution thresholdによる反発判定と反復ソルバの目標速度への収束が期待どおりに機能した。

これまでに検証した複数接触点、累積法線力積、累積摩擦力積、反発目標速度方式と合わせ、Phase 5の主要機能の実装・基本検証を完了とする。

長時間の静止接触および積み重ねの安定性はPhase 6で検証する。

## Phase 6：Circle–Wallの共通Contact Solver化

### 目的

従来は壁衝突を専用の`resolveWallCollision()`で処理していたが、Circle–Wallについて既存のSequential Impulse Solverへ統合した。

静的Bodyを導入し、動的Circleとの衝突を通常のContactManifoldで扱えることを確認する。

### 実装内容

- `Body`に`isStatic`を追加し、静的Bodyの逆質量・逆慣性を0とした。
- 静的Bodyを重力・速度・位置・角度の更新対象から除外した。
- Circle–Wallの接触情報を、WallをBody A、CircleをBody BとしてContactManifoldへ格納するよう変更した。
- 接触法線をWallからCircleへ向かう方向に統一した。
- Manifoldのgetterを使い、静的Bodyを含む接触では壁用の反発係数・摩擦係数を選択するよう変更した。
- 静的Body同士のManifoldを登録しない処理を追加した。
- 法線・接線方向の有効質量、および位置補正におけるゼロ除算対策を追加した。
- Circle–Wallでは旧`resolveWallCollision()`を使用せず、共通Solverで応答するよう変更した。

### 検証条件

- 対象：動的Circle 1個と静的床
- 重力：98.0
- 固定時間刻み：1/60秒
- Solver Iterations：10
- 反発係数：検証時の初期ログでは0.5（修正前はOBJRESTITUTIONを使用）
- 摩擦係数：0.5
- Restitution Threshold：10.0

### 検証1：静的Bodyとの法線応答

共通Solverへの移行直後、Circleの床衝突を2回記録した。

初回のログ：

```text
vn_before = -309.19
targetVel = 154.595
vn_after = 154.595
```

2回目のログ：

```text
vn_before = -154.105
targetVel = 77.0523
vn_after = 77.0523
```

いずれも`e = 0.5`に対応する目標速度へ到達した。

また、静的Body側の逆質量・逆慣性はともに0であり、法線方向の有効質量には動的Circle側の寄与のみが残ることを確認した。

iteration 0で目標速度へ到達した後、残りのiterationでは法線速度が維持され、反発が繰り返し増幅される挙動は見られなかった。

なお、このログの時点では壁用の反発係数ではなく物体用の反発係数が適用されていたため、その後Manifoldのgetterによる選択方式に修正した。

### 検証2：床上での転がり挙動

Circleが床と接触した後、横方向の移動が継続する現象を確認した。

代表ログ：

```text

targetVel = 0
vn_after = 0

vx_before = 36.1311
vt_before = 0
friction_clamped = false
vx_after = 36.1311

```

この状態では、接触点の接線方向相対速度`vt`が既に0であるため、摩擦Solverによる追加の接線方向速度補正は不要となる。

円の中心速度が0でなくても、回転によって接触点速度が打ち消されれば、滑らずに転がる状態となる。

したがって、横方向の移動が継続することは現在の物理モデルと整合している。

現状のCoulomb摩擦Solverは接触点の滑りを抑えるものであり、純粋転がり自体を減速させる転がり抵抗は実装していない。

今回の現象はSolverの不具合とは判断せず、転がり抵抗は将来の追加機能として扱う。

### 結果と今後の課題

Circle–Wallについて、静的Bodyを含むContactManifoldの生成と、共通Sequential Impulse Solverによる応答を実装した。

数値ログでは、法線速度が目標速度へ到達し、iterationの増加によって過剰な反発が発生しないことを確認した。

また、静的Body同士の除外、ゼロ除算対策、壁用物理パラメータの選択をコード上で追加した。

ただし、修正後の壁用反発係数を使った数値比較や長時間の静止安定性は今回のログでは評価していない。

次はPolygon–Wallを共通Manifoldへ接続し、床との辺接触を2点Contactとして扱う。その後、位置補正の安定化と静止接触・積み重ねの検証を行う。

## Phase 6：Polygon–Wallの共通Contact Solver化と2点接触の検証

### 目的

Polygon–Wallの衝突応答を従来の壁専用処理から共通Contact Solverへ統合し、静的床・壁に対して複数接触点を用いたSequential Impulseが機能することを確認する。

また、矩形の水平落下時に発生した残留角速度と接触点数の変化について、その原因を数値的に調査する。

### 実装内容

- Polygon–Wallの接触情報をContactManifoldとして登録する処理を実装した。
- 壁を静的Body A、Polygonを動的Body Bとして扱う。
- 床・壁に近い複数の頂点をContact候補として登録する処理を追加した。
- 静的Bodyを積分・力積適用の対象から除外した。
- 静的Bodyの逆質量・逆慣性を0として共通Solverで処理した。
- 従来のresolveWallCollision()は使用せず、共通Solverで応答する構成に変更した。

### 検証条件

基本設定：

- 重力：98.0
- 固定時間刻み：1/60秒
- 壁の反発係数：0.5
- 壁の摩擦係数：0.5
- Restitution Threshold：10.0
- Solver Iterations：10
- 接触候補判定EPSILON：最終的に2.0を暫定採用

接触点数と回転の追加検証では、矩形の高さを30に固定し、幅10・30・50・80、EPSILON=0.1で比較した。iteration数30の条件も確認した。

### 検証1：共通Solverによる反発

床との2点接触に対してSequential Impulseを適用した。

代表例：

```text
1回目のバウンド
targetVel = 161.7
iteration 9:
  contact 0 vn_before = 161.684
  contact 1 vn_before = 161.691

2回目のバウンド
targetVel ≈ 80.035
iteration 9:
  contact 0 vn_before = 80.0337
  contact 1 vn_before = 80.0283

3回目のバウンド
targetVel ≈ 40.016
iteration 9:
  contact 0 vn_before = 40.0138
  contact 1 vn_before = 40.0140
```

各接触点の法線方向速度は、iterationを重ねることで目標速度へ収束した。

また、反発速度はバウンドごとにほぼ半減しており、反発係数0.5と整合した。

### 検証2：静的Bodyの不変性

共通Solverのiteration終了時に静的Bodyの状態を確認した。

```text
staticObj vel = (0, 0)
staticObj omega = 0
staticObj pos = (0, 0)
```

接触点0・1の双方で、静的Bodyの速度・角速度・位置が変化しないことを確認した。

旧resolveWallCollision()にデバッグ出力を追加して呼び出し状況を確認したが、当該出力は発生しなかった。提示コード上でも呼び出しが存在しない。

これにより、今回の動作経路では旧壁応答との二重処理がないことを確認した。

### 検証3：接触点数と残留角速度

完全水平の矩形を落下させる条件で、矩形の幅とSolver Iterationsによる残留角速度の違いを確認した。

高さ30、EPSILON=0.1、iteration=10での初回衝突終了時の角速度：

| 幅 | 角速度 rad/s |
|---|---:|
| 10 | 0.607761 |
| 30 | 0.00213631 |
| 50 | -0.0000595061 |
| 80 | -0.0000736506 |

矩形の幅によって、有限反復終了時の残留角速度が大きく異なった。

幅10の条件でiteration数を30へ増加させると、初回衝突終了時の角速度は0.007193 rad/sまで減少した。

一方、2回目の床衝突時には次の状態となった。

```text
angle = 0.023617 rad
angularVel_before = 0.007193 rad/s
deltaY = 0.236145
EPSILON = 0.1
contactNum = 1
angularVel_after ≈ -3.33837 rad/s
```

初回衝突後の残留角速度が飛行中に姿勢変化として蓄積され、2回目の衝突では底辺の2頂点の高さの差がEPSILONを超えた。

幅10の矩形について、

```text
deltaY ≈ 10 × sin(0.023617)
       ≈ 0.23615
```

となり、実際のdeltaYと一致した。

このため、2回目の衝突では1点Contactとして判定され、偏心衝突によって大きな角速度変化が生じたと考えられる。

### 考察と暫定方針

今回の現象には、以下の要因が関係している。

- 2点接触に対するSequential Impulseの有限反復誤差
- 形状・慣性モーメントによる収束速度の違い
- 衝突間における残留角速度の蓄積
- EPSILONによる接触候補数の切り替わり

EPSILONを大きくすると2点接触が維持されやすくなる一方、壁から離れた頂点を接触候補に含める可能性もある。

現段階では、Solver Iterations=10、EPSILON=2.0を暫定設定として採用する。

有限反復による残留角速度や接触点数の切り替わりは既知の制限として残し、過剰なパラメータ調整は行わない。

### 結論

Circle–WallおよびPolygon–Wallを共通Contact Solverへ接続し、静的Bodyを含む衝突応答を実装した。

Polygon–Wallでは、床との2点Contactに対するSequential Impulseの収束を確認した。

また、静的Bodyが応答によって移動・回転しないこと、旧壁応答と二重処理されないことを確認した。

以上により、Phase 6の「静的床・壁の共通ソルバ化」を一区切りとする。

次はpenetration slopと位置補正率を導入し、静止接触、振動、回転、ドリフト、残留めり込みの安定性を検証する。

なお、長時間の静止安定性および積み重ねの合格判定は未実施であり、次の検証項目で扱う。

## Phase 6：位置補正の安定化とStacking検証

### 目的

従来のpenetration全量補正に対して、penetration slopと位置補正率を導入し、位置補正量を調整可能にする。

また、単体Rectangleと静的床、およびRectangle 3個のstackingについて、位置補正パラメータがめり込み・回転・静止安定性に与える影響を確認する。

### 実装内容

位置補正量を以下の式で計算するように変更した。

\[
d_{\mathrm{correction}}=\beta\max(p-s,0)
\]

- \(p\)：検出されたpenetration
- \(s\)：penetration slop（許容めり込み）
- \(\beta\)：位置補正率

補正後の移動量は従来どおり逆質量比で各Bodyに分配する。

slopは微小なめり込みを許容するため、補正率は1stepで修正する位置誤差の割合を調整するために使用する。

位置補正は速度Solverのiterationとは独立しており、各Manifoldに対して1回実行する。補正中のpenetration再計算や位置拘束の反復処理は導入していない。

### 検証1：既存処理との一致

SingleBoxシーンで、従来の全量補正と新方式を比較した。

\(\beta=1.0,\ s=0.0\) とした場合、penetration、位置補正量、実際の移動量について従来と同じ結果が得られた。

代表ログ：

```text
penetration     = 2.52142
correctionValue = 2.52142
deltaA          = 0
deltaB          = 2.52142
contactNum      = 2
```

これにより、新方式でもβ=1、slop=0の場合には従来の全量補正を再現できることを確認した。

### 検証2：slopと補正率による補正量の変化

SingleBoxでslopおよびβを変更した。

代表的な初回衝突の結果：

| β | slop | penetration | correctionValue |
|---|---|---|---|
| 1.0 | 0.0 | 2.52142 | 2.52142 |
| 1.0 | 0.1 | 2.52142 | 2.42142 |
| 1.0 | 0.5 | 2.52142 | 2.02142 |
| 1.0 | 1.0 | 2.52142 | 1.52142 |
| 0.5 | 1.0 | 2.52142 | 0.760712 |
| 0.1 | 1.0 | 2.52142 | 0.152142 |

slopの増加によって補正対象量が減少し、βの減少によって実際の補正量が小さくなることを確認した。

また、penetrationがslop以下の場合には位置補正量が0となることを確認した。

SingleBoxでは、設定変更による見た目の大きな違いは確認されなかった。角速度も小さい値を示しており、今回の条件では大きな回転の増幅は見られなかった。

ただし、補正率を変更したことによる明確な静止安定性の改善までは確認できなかった。

### 検証3：Rectangle 3個のStacking（60秒）

同一の初期条件で、Rectangle 3個を積み重ねるシミュレーションを60秒間実行した。

基本条件：

- 重力：98.0
- Fixed timestep：1/60秒
- Solver Iterations：10
- 壁・物体の反発係数：0.5
- 壁・物体の摩擦係数：0.5
- Restitution Threshold：10.0
- 接触候補判定EPSILON：2.0

比較条件：

| 条件 | β | slop |
|---|---|---|
| 1 | 1.0 | 0.0 |
| 2 | 1.0 | 1.0 |
| 3 | 0.1 | 1.0 |
| 4 | 0.5 | 1.0 |

検証には各条件のCSVログと60秒経過後の画像を使用した。また、条件3・4については途中で生じた跳ね上がりを動画でも確認した。

#### 結果

4条件とも、60秒経過後にはRectangle 3個の積み重なりが維持されていた。

見た目上、条件間に大きな違いはなかったが、数値では残留penetrationに差が見られた。

β=1.0、slop=0.0では残留penetrationが小さく、slop=1.0では許容めり込みが増加した。

さらにβを小さくすると、めり込みの修正が緩やかになり、残留penetrationが増える傾向が確認された。

また、条件3・4では積み重なりの途中で一時的な跳ね上がりが発生した。

60秒後には大きな崩壊は確認されなかったものの、横方向の位置ずれや微小な回転は残った。

#### 考察

補正率を小さくすると1stepあたりの位置修正量は減少するが、必ずしも静止安定性が向上するわけではなかった。

今回の条件では、従来の全量補正に明確な問題は確認されず、βを小さくすることによる一貫した改善も確認できなかった。

一時的な跳ね上がりについては、速度Solverの反発応答、接触点数の変化、位置補正による物体配置の変化などが関係している可能性がある。ただし、直接原因は特定していない。

位置補正による移動はBodyの位置のみを変更するため、角速度を直接変化させるものではない。回転への影響は接触状態の変化を通じて間接的に発生し得る。

### 採用する設定

今回の結果から、以下を暫定設定として採用する。

```text
PENETRATIONSLOP = 1.0
PENETRATIONBETA = 1.0
```

slop以下のめり込みを許容し、それを超過した分について全量補正する方式とする。

本設定が最適であると確認したわけではないが、今回の検証条件では大きな崩壊がなく、補正率を小さくする明確な利点も確認されなかったため、これ以上のパラメータ調整は行わない。

### 残る制限

- 接触点数が変化する場合に、一時的な跳ね上がりが発生することがある。
- 横方向driftや微小な姿勢変化が残る。
- 位置補正は各Manifoldに対して1回のみ実行し、補正後のpenetrationは同一step内で再計算していない。
- 複数Manifold間での位置補正の相互作用を反復的に解く方式は未実装。
- EPSILON=2.0はPolygon–Wallの接触候補判定に用いる暫定値であり、接触点数と描画上の違和感について改善余地がある。

これらは既知の制限として記録し、現段階では追加の位置Solver、warm starting、sleep等は導入しない。

### Phase 6の結論

Phase 6では、Circle–WallおよびPolygon–Wallの共通Contact Solver化、静的Bodyの導入、位置補正へのslopと補正率の追加を行った。

静的床との接触や2点Contactでの応答を確認し、単体Rectangleと3個のRectangleのstackingについて基本的な動作検証を実施した。

60秒間のstackingで大きな崩壊は確認されなかったが、完全な静止や誤差ゼロは達成していない。また、位置補正パラメータの変更による明確な安定性改善も確認されなかった。

以上を踏まえ、Phase 6は既知の制限を残した状態で一区切りとする。

## 2D最終検証：V-01〜V-05

### 目的

Phase 5・6までに実装した2D剛体物理について、基本的な検証シーンを実行し、重大な不具合が発生しないことを確認する。

過去の数値検証を活用し、今回は最新の物理実装における描画上の挙動、静止接触、積み重ね、摩擦、Solver Iterationsの影響を中心に確認した。

### 共通設定

基本設定は以下とする。

- 重力：98.0
- Fixed timestep：1/60秒
- 反発係数：0.5
- 摩擦係数：0.5（V-04では変更）

- Solver Iterations：10（V-05では変更）

### V-01：単体Rectangleと静的床

確認結果：

- 不要な回転が継続する挙動は見られなかった。
- 見た目上、大きな異常は確認されなかった。

Phase 6で実施した位置補正の数値検証と合わせ、今回のSingleBox条件では基本的な床接触が成立していると判断した。

### V-02：Rectangle 3個のStacking

Phase 6で実施した60秒間のStacking検証結果を使用した。

同一初期条件でPenetration SlopとBetaを変更し、めり込み・回転・横方向drift・積み重なりの維持を比較した。

採用設定：

```text
PENETRATIONSLOP = 1.0
PENETRATIONBETA = 1.0

```

確認結果：

- 60秒間のシミュレーションで大きな崩壊は確認されなかった。

- 横方向drift、残留めり込み、微小な姿勢変化は残った。

### V-03：Circle・Rectangle・Triangle混在

固定seedのRandomシーンを実行し、Circle、Rectangle、Triangleが混在する状態での挙動を観察した。

#### 描画による確認

- 3種類の形状が混在するシミュレーションを実行できた。
- 複数物体が接触した状態でも、目視上、大きな振動や突然の異常な移動は見られなかった。
- 過剰な反発や大きな吹き飛びは確認されなかった。
- 静止状態に近づいた後も、物体同士の接触が維持された。
- 一部で軽微なめり込みや姿勢のずれが見られた。

軽微なめり込みにはPenetration Slopが関係している可能性がある。また、Polygon–Wallの接触候補判定に使用するEPSILONは、残留姿勢や見た目の違和感に影響する可能性がある。

ただし、今回の検証では各要因の寄与を個別に測定していない。

`updatePhysics()`の最後で、各PolygonおよびCircleのBodyに対して`std::isfinite()`による数値チェックを実施した。

- `pos.x / pos.y`


**判定：合格**

### V-04：摩擦あり／なしの比較

固定seedのRandomシーンを使用し、物体同士および物体と壁の摩擦係数を変更して比較した。

比較条件：

- μ=0.0：物体間・壁接触とも摩擦なし
- μ=0.5：物体間・壁接触とも摩擦あり

確認結果：

- μ=0の場合、接線方向の相対運動が抑制されず、横方向への移動が継続した。
- 摩擦による衝突応答の変化に伴い、物体の最終配置にも違いが生じた。
- μ=0.5では横方向の移動が抑えられ、静止状態へ近づく挙動が観察された。
- どちらの条件でも、目視上、重大な異常は確認されなかった。

この結果は、Phase 5で確認した累積接線力積によるCoulomb摩擦の数値検証とも整合する。

摩擦が物体の接線方向運動を抑制していることを、数値検証と描画の両方から確認できた。

標準設定はμ=0.5を維持する。

**判定：合格**

### V-05：Solver IterationsによるStacking比較

Rectangle 3個のStackingシーンを使用し、Solver Iterationsを変更してシミュレーション時間60秒後の状態を比較した。

比較条件：

| Solver Iterations | 60秒後の観察結果 |
|---|---|
| 1 | Rectangle 3個が分離し、積み重なりが崩れた |
| 5 | 積み重なりはおおむね維持されたが、位置ずれが大きい |
| 10 | 積み重なりを維持。段差や微小なずれが残る |
| 15 | 積み重なりを維持。比較的小さな位置ずれ |
| 20 | 積み重なりを維持。比較的小さな位置ずれ |
| 30 | 比較条件の中では最も整列して見える |

#### 考察

Sequential Impulseでは、接触点に力積を適用すると別の接触点の速度状態も変化する。

iteration数を増やすことで、接触点間の相互作用を繰り返し修正できるため、複数の接触拘束をよりよく満たせる場合がある。

今回のStackingでは、iteration数が少ない条件ほど積み重なりが崩れやすく、iteration数を増やすことで位置ずれが小さくなる傾向が確認された。

この結果は、Phase 5で確認した法線方向相対速度の反復収束とも整合している。

一方、今回の比較は主に60秒経過後の描画状態を用いたものであり、各条件の計算時間、途中の最大振動、penetrationの時系列を定量的に比較したものではない。

したがって、30iterationが性能も含めて最適であるとは判断できない。

現段階では10iterationでも積み重なりを維持できているため、標準設定は10のままとする。iteration数の増加による計算負荷と安定性の評価は、今後必要になった場合に実施する。

**判定：合格**

### 総合評価

V-01〜V-05の基本的な検証を実施した。

単体Rectangleと静的床、Rectangle 3個の積み重ね、Circle・Rectangle・Triangle混在、摩擦係数による比較、Solver Iterationsによる比較について、期待される基本的な挙動を確認できた。

残る制限は以下のとおり。

- 横方向driftおよび軽微なめり込みが残る。
- 一部の条件では、一時的な跳ね上がりが発生する。
- 接触点候補判定EPSILONは暫定値であり、姿勢や接触点数への影響が残る。
- NaN・Infの検証は各step終了時点のBody状態を対象とし、全中間計算を検証したものではない。
- Solver Iterationsと計算負荷の定量的な比較は未実施。

以上から、2D剛体物理の基本機能に関する最終検証は一区切りとする。

ただし、2D完成判定はコード整理、ビルド・実行確認、ドキュメント整備を終えた後に実施する。

今後は機能追加や細かなパラメータ調整を優先せず、物理更新とSandboxの分離、デバッグ出力の整理、README整備、GitHub公開を進める。

## 2D物理エンジン：Physics2D / Sandboxの構造整理と回帰確認

## 撮影用SingleBoxにおける床衝突時の摩擦応答検証

### 目的

デモ動画の撮影のため、SingleBoxに水平方向の初速度を設定して斜方に落下させたところ、床との初回衝突時に水平速度がほぼ0となり、垂直に近い方向へ跳ね返る現象が発生した。

壁の摩擦係数μを0.5から0.1へ変更すると横速度が残るようになったため、接触点の摩擦力積と速度変化を確認し、Solverの動作との整合性を検証した。

### 検証条件

- 対象：Rectangle 1個と静的床（SingleBox）
- 矩形サイズ：80 × 60、質量：2.375
- 初期位置：`Vec2(W / 5.0f, H / 2.0f)`
- 初期速度：`Vec2(100.0f, 0.0f)`
- 重力：98.0、固定時間刻み：1/60秒
- 壁の反発係数：0.5
- Solver Iterations：10
- 壁の摩擦係数：μ = 0.1 / 0.3 / 0.5

床への初回衝突について、各接触点のクランプ前後の累積接線力積、摩擦力積の適用差分、接線相対速度、重心の水平速度を記録した。

### 検証結果

| μ | 最終水平速度 vx | 観察結果 |
|---|---:|---|
| 0.1 | 65.455 | 接線相対速度が残り、斜め方向への反発が見られた |
| 0.3 | 0.0538 | 水平速度がほぼ0となった |
| 0.5 | 0.0262 | 水平速度がほぼ0となった |

μ=0.1では、最終iterationで両接触点の累積接線力積がCoulomb摩擦の制限に達していた。追加の摩擦力積を適用できず、接線相対速度が残った。

一方、μ=0.3および0.5では、今回の衝突条件において接触点の接線相対速度がほぼ0となり、重心の水平速度もほぼ消失した。

なお、接線相対速度`vt`は重心速度`vx`と必ずしも一致しない。接触点速度には角速度による成分が含まれ、摩擦力積は並進速度と角速度の両方を変化させる。

### 水平運動量変化と摩擦力積の照合

床の接触法線が鉛直であるため、床からの接線力積は水平方向に作用する。

最終累積接線力積の和と、初回衝突前後の水平運動量変化を比較した。

| μ | 累積接線力積の和 | 水平運動量変化 |
|---|---:|---:|
| 0.1 | -82.0443 | -82.0444 |
| 0.3 | -237.3720 | -237.3723 |
| 0.5 | -237.4379 | -237.4378 |

水平運動量変化は、`Δpx = m × (vx_after - vx_before)`から計算した。

各条件で両者が丸め誤差の範囲で一致したことから、今回の床接触では、摩擦力積による水平速度の更新が計算と整合していることを確認した。

### 考察・結論

今回の摩擦Solverは、接触点の接線相対速度を0へ近づける補正力積を求め、累積法線力積に基づくCoulomb摩擦の範囲内に制限している。

μが小さい場合は、摩擦力積が上限に達すると接線相対速度が残る。一方、今回のμ=0.3以上では接線相対速度をほぼ0にでき、結果として重心の水平速度もほぼ消失した。

したがって、初回衝突で横方向の移動がほぼ停止する現象は、今回の摩擦モデルおよび検証条件と整合しており、現時点ではSolverの不具合とは判断しない。

既定の壁摩擦係数μ=0.5は維持する。デモ撮影時には条件を明示して摩擦係数を変更し、摩擦の強さによる挙動の違いを紹介する。今回の検証結果だけから、一般的に適切な摩擦係数を決定したわけではない。
